## 1. 项目目标与边界

- 项目定位：门店内部知识培训问答系统（非面向顾客导购）。
- 核心闭环（Must Have）：登录鉴权 -> 文件上传 -> 异步处理 -> 向量入库 -> RAG问答 -> 来源引用。
- 明确不做：音视频处理、微服务拆分、移动端适配、多租户、知识版本管理系统。

## 2. 统一技术口径

- 架构：Spring Boot 3.x 模块化单体 + Python FastAPI AI服务 + Vue 3 前端。
- 后端：Spring Boot、Spring Security + JWT、MyBatis-Plus、Spring AMQP、WebFlux(SSE)。
- AI与检索：本地 Embedding（`bge-small-zh`）+ MySQL FULLTEXT(BM25) + Milvus 向量检索 + RRF 融合。
- 存储与中间件：MySQL 8、Redis 7、RabbitMQ 3.12、MinIO、Milvus 2.x、etcd 3.5.5。

## 3. 不可变核心参数

- `chunk_size=400`
- `chunk_overlap=80`
- `vector_dim=512`
- `bm25_topk=5`
- `vector_topk=5`
- `rrf_k=60`
- `rerank_top=5`
- `context_max_round=3`
- `milvus_collection=knowledge_vectors`
- `minio_bucket=beauty-knowledge`
- MySQL 中文检索：`ngram_token_size=2`

## 4. 模块边界（后端）

- `common`：统一返回、异常、工具类、常量。
- `config`：Security、Redis、RabbitMQ、Milvus、MinIO、Web/CORS 配置。
- `module.auth`：登录、登出、当前用户信息、JWT校验。
- `module.cms`：分类、知识内容、文件上传与任务状态查询。
- `module.pipeline`：消费MQ、文本提取、分块、向量化、任务状态推进。
- `module.rag`：意图识别、混合检索、RRF融合、Prompt组装、流式输出。
- `module.entity`：成分/功效/产品、关系绑定、实体抽取待确认。
- `infrastructure`：LLM接口抽象、Python AI客户端、Milvus/MinIO防腐封装。

## 5. 关键数据链路

### 5.1 入库链路

1. 上传文件 -> 计算`file_hash`去重。  
2. 上传到 MinIO，写`kb_file(process_status=PENDING)`与`process_task(status=PENDING)`。  
3. 发送 RabbitMQ 持久化消息。  
4. 消费者处理：`PROCESSING` -> 文本提取（PDF:Tika / 图片:OCR） -> 分块 -> 向量化 -> 入Milvus。  
5. 成功落`SUCCESS`，失败入DLQ并标记`FAILED`，支持手动重试。

### 5.2 问答链路

1. 用户提问，读取最近3轮上下文。  
2. 双路召回：MySQL FULLTEXT + Milvus 向量检索。  
3. Java层 RRF 融合并 rerank。  
4. LLM 流式生成答案，返回`answer + sources(file/page/chunk)`。  
5. 前端按流式文本展示，并可展开引用来源。

## 6. API 基线（首版）

- 认证：`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/info`
- 分类：`GET /api/category/tree`、`POST /api/category`、`PUT /api/category/{id}`、`DELETE /api/category/{id}`
- 知识：`GET /api/knowledge/page`、`GET /api/knowledge/{id}`、`POST /api/knowledge`、`PUT /api/knowledge/{id}`、`DELETE /api/knowledge/{id}`、`GET /api/knowledge/search`
- 文件与任务：`POST /api/file/upload`、`GET /api/file/task/{taskId}`、`POST /api/file/task/{taskId}/retry`、`DELETE /api/file/{fileId}`
- 实体：`GET /api/entity/pending`、`POST /api/entity/confirm`、`GET/POST /api/entity/ingredient`、`GET/POST /api/entity/product`、关系绑定接口2个
- 聊天：`GET /api/chat/stream`、`GET /api/chat/session`、`GET /api/chat/session/{sessionId}/messages`、`DELETE /api/chat/session/{sessionId}`

统一返回：`Result<T>`，错误码包含 `1001~1006` 业务码。

## 8. 部署基线与冲突决议

### 8.1 环境模式

- 推荐模式（统一复现）：全部中间件走 Docker Compose。
- 兼容模式（当前机器可用）：MySQL/Redis 走本机，RabbitMQ/MinIO/Milvus/etcd 走 Docker（`docker compare.docx`）。

### 8.2 版本/配置冲突处理

- Milvus 版本：统一按 `2.x`，以 `2.5.4` 为优先目标（`完整指南.md`）。
- LLM 提供方：统一保留接口抽象；开发默认可用 `ollama(qwen2.5:7b)`，生产可切通义千问。
- 鉴权与响应规范：以 `Result<T> + JWT + Redis黑名单` 为唯一口径。

## 9. 里程碑（执行版）

1. 第1周：环境与工程初始化（Compose、配置、DDL、common/config）。
2. 第2周：认证模块与CMS基础CRUD打通。
3. 第3周：文件上传 + MQ消费 + 处理任务闭环。
4. 第4周：RAG最小闭环（可提问、有引用、可流式）。
5. 第5周：实体抽取确认与前端管理页完善。
6. 第6周：稳定性、压测、答辩数据准备。

## 10. 验收红线

- 中间件健康可用，14张表完整。
- 上传文件后任务状态可从`PENDING -> PROCESSING -> SUCCESS/FAILED`。
- 问答必须返回来源引用；禁止无依据回答。
- 全接口统一`Result<T>`，统一异常处理，禁止裸异常与`null`返回。
- 关键链路日志可追踪，可定位任务失败原因。
