# 完整指南第5-6阶段补全（可执行版）

更新时间：2026-03-16

## 第五阶段：Pipeline 处理流水线（补全）

### 目标
- 打通 `上传文件 -> 异步处理 -> 分块 -> 向量入库 -> 状态回写` 全链路。

### 数据表依赖
- `kb_file`
- `kb_chunk`
- `process_task`

### 核心类清单
1. `module/pipeline/domain/dto/ChunkDTO.java`
2. `module/pipeline/domain/message/KnowledgeProcessMessage.java`
3. `module/pipeline/service/ChunkService.java`
4. `module/pipeline/service/ProcessTaskService.java`
5. `module/pipeline/consumer/KnowledgeProcessConsumer.java`
6. `module/cms/mapper/KbChunkMapper.java`
7. `module/cms/mapper/xml/KbChunkMapper.xml`

### 处理流程
1. 消费消息后将 `process_task.status` 与 `kb_file.process_status` 更新为 `PROCESSING`。
2. 从 MinIO 下载文件字节。
3. PDF 走 Tika 抽取文本，图片走 Python OCR 接口。
4. 按 `chunk_size=400`、`chunk_overlap=80` 分块并记录页码。
5. 调 Python `/embed` 批量向量化，写入 Milvus。
6. 批量写入 `kb_chunk`。
7. 成功回写 `SUCCESS`，失败回写 `FAILED` 并记录错误信息。

### 状态机
- `PENDING -> PROCESSING -> SUCCESS`
- `PENDING -> PROCESSING -> FAILED -> (retry) -> PENDING`

### 验收清单
- [ ] 上传文件后 `process_task` 从 `PENDING` 进入 `PROCESSING`
- [ ] 处理成功后 `kb_chunk` 有分块数据
- [ ] Milvus 中可检索到对应向量
- [ ] 处理失败任务可通过重试接口再次入队

## 第六阶段：RAG 智能问答引擎（补全）

### 目标
- 打通 `问题输入 -> 混合检索 -> RRF融合 -> LLM生成 -> 引用返回`。

### 检索层核心类
1. `module/rag/domain/dto/ChatRequest.java`
2. `module/rag/domain/dto/ChunkResult.java`
3. `module/rag/domain/dto/ChatMessage.java`
4. `module/rag/service/IntentService.java`
5. `module/rag/service/ContextService.java`
6. `module/rag/service/HybridSearchService.java`
7. `module/rag/mapper/KbChunkSearchMapper.java`
8. `module/rag/mapper/xml/KbChunkSearchMapper.xml`

### 生成层核心类
1. `module/rag/service/PromptService.java`
2. `module/rag/service/ChatService.java`
3. `module/rag/controller/ChatController.java`
4. `module/rag/domain/entity/ChatSession.java`
5. `module/rag/domain/entity/ChatMessageEntity.java`
6. `module/rag/mapper/ChatSessionMapper.java`
7. `module/rag/mapper/ChatMessageMapper.java`

### 问答流程
1. 接收 `question` 与 `sessionId`。
2. 读取 Redis 最近 3 轮上下文。
3. 并行召回：
   - MySQL FULLTEXT（BM25 TopK=5）
   - Milvus 向量检索（TopK=5）
4. RRF 融合（`k=60`），取 `rerank_top=5`。
5. 组装 Prompt（按意图模板）。
6. 调用 `LLMProvider.streamChat()` 输出 SSE。
7. 落库会话与消息，同时返回 `sources(file/page/chunk)`。

### 接口清单
- `GET /api/chat/stream`（SSE）
- `GET /api/chat/session`
- `GET /api/chat/session/{sessionId}/messages`
- `DELETE /api/chat/session/{sessionId}`

### 验收清单
- [ ] SSE 流式输出可用
- [ ] 每条回答有引用来源
- [ ] 混合检索结果优于仅向量检索
- [ ] 会话历史可查看、可删除
