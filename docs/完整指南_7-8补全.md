### 任务2：关联关系管理

#### 核心类清单
1. `module/entity/domain/entity/RelIngredientEffect.java`
2. `module/entity/domain/entity/RelProductIngredient.java`
3. `module/entity/service/RelationService.java`

#### 关键规则
1. 关系表使用联合唯一键避免重复绑定。
2. 绑定前校验两端实体存在性。
3. 删除实体时校验/清理关联关系，防止脏数据。

#### 接口清单（示例）
- `POST /api/entity/relation/ingredient-effect`
- `DELETE /api/entity/relation/ingredient-effect`

---

### 任务3：实体抽取 + 确认

#### 核心类清单
1. `module/entity/domain/entity/EntityExtractPending.java`
2. `module/entity/domain/dto/EntityExtractResult.java`
3. `module/entity/mapper/EntityExtractPendingMapper.java`
4. `module/entity/service/EntityExtractService.java`
5. `module/entity/service/EntityConfirmService.java`
6. `module/entity/controller/EntityController.java`

#### 处理流程
1. Pipeline 处理文档后触发抽取服务。
2. 先词典匹配，再 LLM 补充抽取。
3. 将候选实体写入 `entity_extract_pending`，状态 `PENDING`。
4. 管理员确认后写入正式实体表并更新状态 `CONFIRMED`。
5. 管理员拒绝则置 `REJECTED`。

#### 验收清单
- [ ] 实体基础 CRUD 可用
- [ ] 关联关系可绑定与解绑
- [ ] 抽取结果可进入待确认列表
- [ ] 管理员确认后写入正式实体表
- [ ] 重复实体名称触发统一业务错误码

## 第八阶段：前端开发（补全）

### 前端状态设计
- `auth`: token、userInfo、isLoggedIn
- `chat`: sessionList、currentSessionId、messages、isStreaming、sources
- `knowledge`: categoryTree、knowledgeList、taskMap
- `entity`: pendingList、ingredientList、productList、pendingCount

### 前端关键流程
1. 登录成功后保存 token，路由守卫按角色分流。
2. 管理员上传文件后跳任务监控页轮询状态。
3. 用户问答页使用 SSE 流式渲染答案。
4. 回答下方展示来源引用（文件名 + 页码 + 原文片段）。

### UI 页面最低交付标准
1. 登录页可完成登录与鉴权失败提示。
2. 管理员端可完成分类、知识、上传、任务、实体确认。
3. 用户端可完成提问、会话切换、历史查看、来源展开。

## 第7-8阶段开发顺序建议
1. 先做第7阶段实体基础 CRUD + 关系管理。
2. 再接实体抽取待确认闭环（后端）。
3. 前端先落路由和状态，再逐页联调。
4. 最后做问答流式体验和任务监控页面细节优化。
